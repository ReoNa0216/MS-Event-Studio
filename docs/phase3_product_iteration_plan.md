# MS Event Studio 下一阶段产品迭代计划

记录日期：2026-08-20（Asia/Shanghai）

适用范围：当前 WebView 桌面版本之后的产品迭代

状态：需求已确认，按本文顺序逐项实现和验收

## 1. 本轮用户目标

1. GitHub 最终只保留一个公开仓库 `ReoNa0216/MS-Event-Studio`，像
   `LMA-Studio` 一样同时承载源码、Actions、版本说明和 Windows/macOS 下载。
   现有 `MS-Event-Studio-Releases` 只在资产迁移和下载验证完成后删除。
2. 修复 macOS 导出审阅结果时“已经选择目标、页面仍认为未选择 CSV 文件”的问题。
3. 完整审计数据包不再要求用户提前创建一个空文件夹。用户只选择正常保存位置，
   应用负责创建最终数据包目录并原子发布。
4. 增加“保留当前窗口内的安全事件”：一次处理当前可见窗口中的未审阅事件，
   但跳过“相邻事件距离较近”的事件，留下它们逐个人工判断。
5. 当前正在判断的事件要比其他事件明显，但不能覆盖事件本身的审阅状态颜色和形状。
6. 主图底部显示时间刻度；时间轴两端增加少量视觉余量，避免峰形贴边。
7. 新建项目时允许设置：
   - 细胞事件 marker m/z，默认 `760.5851`；
   - “相邻事件距离较近”的阈值，默认 `0.60 s`。
8. 量化并优化冷启动速度，至少达到启动过程可解释、可测量；优化方向参考 LMA Studio，
   但不复制与本产品无关的复杂结构。

## 2. 第一性原理与不可破坏的边界

### 2.1 审阅与批量操作

- 自动检测负责提供证据，人工审阅负责给出决定；批量操作不能改变自动证据。
- 批量保留只处理执行瞬间绑定的窗口快照中的 `unreviewed` 事件。
- 已保留、已排除和待定是已经表达过的人工决定，不被批量操作覆盖。
- `collision_risk_high=true` 的事件始终跳过；事件间距必须由服务端用项目阈值复验，
  不能信任浏览器传来的布尔值。
- 一次批量操作是一个事务和一个可撤销命令：要么全部成功，要么零写入。
- 操作前显示将保留、跳过和不变的数量；完成后选择第一个仍需人工判断的事件。

### 2.2 当前事件视觉语义

- 状态仍由既有形状和状态色表达；当前选择不能把“未审阅/保留/排除/待定”颜色改写。
- 当前事件使用独立的高对比轮廓、光环或竖向引导线表达，并在密集峰中仍可辨认。
- 选择高亮不能遮住实际峰顶，不能扩大科学 hit target，也不能改变标签集合。

### 2.3 科学参数

- marker m/z 是科学身份参数，不是显示偏好。它决定原始 m/z 提取、ppm 误差、峰调用、
  自动事件身份、项目代次和导出证据。
- marker 在创建项目前确认，项目创建后保持不可变；修改 marker 应创建新项目，
  不在旧项目上静默重算。
- ppm 窗口本轮仍固定为闭区间 ±12 ppm。marker 可配置不等于放宽质量窗口。
- 最新 LMA Studio v0.4.11 仍使用预先声明的 `760.5851` marker，没有可直接照搬的
  任意 marker 项目设置。因此本仓库需要完成自己的、边界清楚的参数化，而不是只改 UI。
- 已逐提交审计 LMA Studio `v0.4.4 → v0.4.5`。v0.4.5 的主要算法变化服务于
  “外部事件坐标 CSV 名单”：对名单中未被核心 caller 命中的坐标，再使用 ±15 ppm 和局部峰形证据
  建立一条独立的辅助审阅通道。MS Event Studio 当前没有外部事件名单输入，因此不移植该通道，
  更不能拿 ±15 ppm 替换现有核心 caller 的固定 ±12 ppm。两者解决的不是同一个问题。
- marker 可配置属于本产品独立的原始信号提取需求：它沿用现有核心 caller，只替换主 marker 的
  m/z 身份，并把数值写入项目来源证据；不会引入 CSV 名单或第二套事件生成逻辑。
- 相邻阈值只决定“需要人工判断”的风险标记，不改变峰是否被检测。它是项目级审阅策略，
  应从 `nearest_event_gap_sec` 动态派生，不进入检峰阈值。
- 新参数必须写入项目清单、检测协议和导出审计；浏览器只能看到用户可理解的摘要。

### 2.4 导出与文件系统

- 浏览器永远不接收绝对路径；原生选择结果立即换成一次性 capability token。
- 审阅结果是一个 `.csv` 文件。原生 SAVE 对话框返回值必须在宿主层规范化：
  处理 macOS 未自动附加扩展名、字符串/序列返回差异和取消操作。
- 完整审计数据包仍保持当前三文件目录合同，不为了方便选择路径而改成另一套数据格式。
- 审计包的选择目标改为“父目录”。应用在该目录下创建带项目名和时间戳的唯一子目录，
  通过同级 staging 原子发布。用户不需要预建目标目录。
- 已存在同名结果不得静默覆盖；自动选择不冲突的名称或明确要求重新选择。
- 导出失败必须清理 staging，不删除用户原有文件，不改变项目和原始 MS 文件。

### 2.5 启动性能

- 先测量，再优化。分别记录进程启动、Python 入口、WebView 创建、本地服务 ready、
  首屏 ready 和工作台数据 ready 的时间。
- 优先检查重型科学库是否在欢迎页出现前被无条件导入，以及打包文件扫描/运行时探针
  是否阻塞可见窗口。
- 欢迎页可见不等于功能 ready；路径选择和打开项目按钮在后端未 ready 时必须明确禁用。
- 不通过删除运行时安全检查、科学 smoke 或单实例保护换取虚假的启动速度。

## 3. GitHub 单仓库收敛方案

当前实测状态：

- `ReoNa0216/MS-Event-Studio`：private，源码和构建工作流所在仓库；
- `ReoNa0216/MS-Event-Studio-Releases`：public，仅含下载说明和
  `v0.3.0-test1` Windows/macOS 预发布资产。

严格按以下顺序操作：

1. 清除源码中的独立 Releases 仓库链接，发布说明统一指向当前仓库的 Releases 页面。
2. 在 `MS-Event-Studio` 上用与构建源码一致的 tag 创建预发布，上传 Windows/macOS ZIP
   与 SHA-256，并验证匿名下载。
3. 验证公开仓库不包含真实原始数据、UAT 项目、SQLite、Parquet、日志、凭据或本机路径。
4. 将 `MS-Event-Studio` 设为 public，复核 Actions 权限、README、许可证和下载链接。
5. 只有在新仓库下载和 Actions 均正常后，删除 `MS-Event-Studio-Releases`。

不得先删除旧仓库，也不得把与源码 commit 不一致的旧二进制冒充为新源码发布。

## 4. 分阶段实现顺序

### P0：基线与对抗式测试骨架

- 冻结当前 HEAD、完整测试、Windows/macOS 路径对话框契约和启动时序基线。
- 新增失败用例：macOS SAVE 返回无 `.csv` 后缀、返回字符串而非序列、取消、同名文件；
  审计父目录非空、同名子目录、写入失败、Parquet 失败和 staging 清理。

退出条件：新测试能稳定复现用户报告的问题，且没有修改科学结果。

### P1：跨平台导出修复

- 统一原生 SAVE 返回值规范化。
- 审计包从“选择最终空目录”改为“选择父目录并由应用创建结果目录”。
- 更新 UI 文案、capability role、API 闭合集合、导出合同和平台测试。

退出条件：Windows/macOS 两种选择路径均可导出；取消零写入；失败无半成品。

### P2：高通量审阅与主图可读性

- 增加窗口批量保留预览/提交 API 和一个清楚的工具栏动作。
- 增加当前事件独立高亮、底部时间刻度和左右视觉余量。
- 覆盖密集峰、窗口边界、筛选状态、撤销/重做、键盘和 100–200% DPI。

退出条件：批量操作不覆盖既有决定、不处理 collision 事件、事务失败零写入；
当前事件在三种标准窗口和密集峰状态中一眼可辨。

### P3：项目科学参数

- 建立单一 `ProjectScientificSettings`：`primary_marker_mz`、固定 ±12 ppm、
  `collision_gap_sec`。
- 参数贯穿检查源、解析、检测、项目清单、打开项目、范围重算、UI 证据和导出。
- 删除硬编码 `pc34_760_*` 对科学身份的依赖，采用角色稳定、数值可变的命名；
  不保留两套新旧执行路径。

项目格式随之升级为单一的 `ms-event-project-v2`。当前仍处于公开测试阶段，旧测试项目不做静默迁移；
需要用原始 MS 文件重新建项目，避免把默认 760.5851 的旧列误解释成用户指定的任意 marker。

退出条件：默认参数与当前黄金结果一致；替代 marker 的合成数据端到端正确；
marker/阈值越界、NaN/Inf、精度歧义和篡改项目均 fail closed。

### P4：启动性能

- 生成源码启动和打包冷启动 flame/timestamp 报告。
- 只对已确认的瓶颈做延迟导入、并行准备或首屏分层。
- 与相同机器上的 LMA Studio 冷启动重复测量对照。

首轮源码导入剖析已经确认：桌面宿主仅仅被 import 时就提前加载 pandas/NumPy/SciPy 和完整科学服务，
累计约 `0.92 s`；将科学项目、审阅工作区和范围重算改为首次使用时导入后，同一命令降至约
`0.13 s`。该优化不删除运行时检查，也不改变用户第一次执行科学操作时加载同一实现的事实。

退出条件：报告记录优化前后中位数和最差值；启动功能、隐藏 smoke 和单实例保护不退化。

### P5：发布与仓库收敛

- 完整自动化、标准截图矩阵、原生 Windows 门禁和 macOS Actions 构建。
- 进行任务流、视觉一致性和 QA/可访问性三类独立对抗式 pre-UAT。
- 迁移发布资产、公开源码仓库、验证匿名下载，最后删除 Releases 仓库。

## 5. 对抗式审查清单

- 批量保留请求发出后窗口、筛选或事件 revision 改变：必须冲突并零写入。
- 批量集合中混入 collision、stale、已排除或待定事件：不得误改。
- macOS 返回不带扩展名、带空格、Unicode 文件名或单个字符串：必须得到正确 CSV。
- 选择 Downloads 等非空目录导出审计包：只能新增一个结果子目录，不能要求清空 Downloads。
- 同名结果、只读目录、磁盘写入失败、Parquet 异常：原文件和项目不变，无 staging 残留。
- 当前事件在最高峰、最低峰、重叠峰、图边缘和对数刻度下都可识别且不遮峰。
- marker m/z 位于数据范围外、过小/过大、NaN/Inf、科学计数法和高精度小数：严格校验。
- 修改 collision 阈值只改变风险提示与批量集合，不改变自动事件数量和身份。
- 冷启动优化后，隐藏 WebView smoke、科学 roundtrip、CSP 和单 renderer 门禁继续通过。
- public 仓库与 release ZIP 中不得出现真实数据、UAT 项目、绝对路径或凭据。

## 6. 本轮明确不做

- 不把 LMA 的外部事件名单辅助通道混入 MS Event Studio 默认自动检测。
- 不开放 ppm、峰高、prominence 等专家参数的任意配置。
- 不让浏览器直接访问文件系统路径。
- 不用逐事件循环请求实现批量操作。
- 不为旧参数格式保留兼容分支、迁移器或 fallback；新科学设置形成一条唯一执行路径。
