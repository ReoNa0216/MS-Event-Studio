# MS Event Studio：marker m/z 的数学原理与验证边界

> 这份文档解释 MS Event Studio 怎样从原始质谱中的 m/z–intensity 数组，得到一条随时间变化的 marker 信号，再从这条信号中识别事件峰。

> 当前产品结论很简单：`760.5851` 是默认值，也是唯一常规推荐值。软件虽然允许输入其他 marker m/z，但其他值目前都属于**实验性设置**，不能因为程序可以运行，就认为它们已经获得与 `760.5851` 相同的科学验证。

## 一、先说最终结论

MS Event Studio 的 marker 流程可以压缩成一句话：

```text
每个 scan 的质心谱
→ 找出目标 m/z ±12 ppm 内的离子
→ 取其中最高强度，得到这个 scan 的 marker 强度
→ 把所有 scan 按时间排成一条 marker trace
→ 从 trace 的安静区估计背景
→ 找出高于背景、且具有足够 prominence 的局部峰
→ 保存峰顶、峰宽、质量误差、相邻距离等证据
```

这里必须区分三件事：

| 问题                                              | 当前答案               |
| ------------------------------------------------- | ---------------------- |
| 程序能否对另一个 m/z 做完全相同的计算？           | 能。                   |
| 相同计算是否必然适合另一个离子？                  | 不能由数学通用性推出。 |
| 目前哪个 m/z 有足够真实数据回归，可作为常规推荐？ | 只有`760.5851`。     |

因此，界面允许修改 m/z 是为了保留受控实验能力，不是宣称“任意 m/z 都同样可靠”。

## 二、m/z 到底是什么

质谱在一个 scan 中给出的不是一条连续曲线，而是一组已经质心化的点：

$$
(m_1,I_1),(m_2,I_2),\ldots,(m_n,I_n)
$$

其中：

- $m_i$ 是第 $i$ 个质心的 mass-to-charge ratio，即 m/z；
- $I_i$ 是这个质心的强度；
- 同一个 scan 中的 $m_i$ 按从小到大排列；
- scan 还有自己的采集时间 $t_s$。

m/z 不是自动确定的化学名称。即使一个信号位于 `760.5851` 附近，MS Event Studio 也只把它当作一个**操作性 marker 通道**；它不会仅凭这个数字证明分子式、加合物、同位素或化学身份。

在当前产品语境里，`760.5851` 常被称为 PC34/MS760 marker。这个名称表示我们用它定位细胞相关事件，不表示软件完成了新的化学鉴定。

## 三、为什么使用 ppm 窗口，而不是固定的 m/z 宽度

仪器的质量误差通常更适合用相对误差表达。对目标质量 $M$ 和观测质量 $m$，ppm 误差定义为：

$$
e_{\mathrm{ppm}}
=\frac{m-M}{M}\times10^6
$$

MS Event Studio 固定使用 ±12 ppm。观测质心被纳入 marker 窗口，当且仅当：

$$
|e_{\mathrm{ppm}}|\le12
$$

等价地，允许的闭区间是：

$$
M(1-12\times10^{-6})
\le m \le
M(1+12\times10^{-6})
$$

### 3.1 `760.5851` 的实际窗口

令：

$$
M=760.5851
$$

半窗宽为：

$$
\Delta M
=760.5851\times12\times10^{-6}
=0.0091270212
$$

所以软件实际读取的闭区间是：

$$
[760.5759729788,\ 760.5942270212]
$$

上下端点都包含在内。窗口总宽约为 `0.018254` m/z。

ppm 的意义是保持相同的**相对误差尺度**。例如：

| 目标 m/z | ±12 ppm 对应半窗宽 |
| -------: | ------------------: |
|      500 |           0.006 m/z |
| 760.5851 |        0.009127 m/z |
|     1000 |           0.012 m/z |

如果对所有质量都使用固定 ±0.01 m/z，那么低质量和高质量处对应的相对误差不同。ppm 避免了这个问题。

### 3.2 为什么不让用户修改 ±12 ppm

当前产品允许修改目标 m/z，但不允许修改 12 ppm 窗口。原因是目标离子和质量容差回答不同问题：

- 目标 m/z 回答“观察哪条质量通道”；
- ppm 容差回答“仪器误差范围内，哪些质心仍算这条通道”。

如果同时任意放宽 ppm，邻近离子、同位素或干扰质心更容易混入；如果任意收窄，正常质量漂移又可能被切掉。现阶段没有足够证据把 ppm 做成普通用户参数，所以固定为 12 ppm。

## 四、一个 scan 怎样变成一个 marker 强度

对第 $s$ 个 scan，定义落入目标窗口的质心下标集合：

$$
\mathcal J_s(M)
=\left\{i:
M(1-12\times10^{-6})\le m_{s,i}\le M(1+12\times10^{-6})
\right\}
$$

marker trace 在这个 scan 上的值定义为：

$$
x_s(M)=
\begin{cases}
\max\limits_{i\in\mathcal J_s(M)} I_{s,i},
& \mathcal J_s(M)\ne\varnothing,\\
0,
& \mathcal J_s(M)=\varnothing.
\end{cases}
$$

也就是说：

1. 窗口内没有质心，marker 强度就是 0；
2. 窗口内只有一个质心，就使用它的强度；
3. 窗口内有多个质心，使用其中**最高强度**，而不是把它们全部相加后用于检峰。

### 4.1 一个具体例子

假设某个 scan 在 `760.5851 ±12 ppm` 内有三个质心：

|      m/z | 强度 |
| -------: | ---: |
| 760.5820 |  120 |
| 760.5854 |  860 |
| 760.5901 |  300 |

这个 scan 的 primary marker trace 值为：

$$
x_s=\max(120,860,300)=860
$$

不是 `1280`。这样可以减少质心化切分或同窗多点把信号虚增的风险。

软件仍会把以下信息作为证据保存：

- 窗口内质心数量；
- 总强度；
- 离目标 m/z 最近的质心及其 ppm 误差；
- 强度最高的质心及其 ppm 误差；
- 最高强度本身。

“离理论质量最近的质心”和“强度最高的质心”可能不是同一个点。程序把两者分开记录，检峰使用后者的强度，质量审阅可以查看相应误差证据。

## 五、从很多 scan 得到时间信号

把所有 scan 按时间排列，就得到：

$$
\left(t_1,x_1\right),
\left(t_2,x_2\right),
\ldots,
\left(t_S,x_S\right)
$$

这就是界面主图中的 primary marker trace。它在概念上类似目标质量窗口的 extracted-ion trace，但当前实现明确取的是“每个 scan 窗口内的最大质心强度”。

```text
强度
  │                            /\
  │               /\          /  \
  │_______/  \____/    \_______
  └──────────────────────────── 时间
            事件1      事件2
```

marker m/z 的修改发生在这一步之前。换 m/z 会重新读取每个 scan、重新形成整条 $x_s(M)$，而不是把旧项目中 `760.5851` 的列改个名字。

因此，修改 marker 必须新建项目；项目会绑定 marker、参数哈希和新一代自动事件，旧项目不会被静默重新解释。

## 六、自动检峰怎样适应背景

MS Event Studio 没有把一个固定强度值写死成所有文件的峰高门槛。它先从当前 marker trace 中寻找相对安静的时间平台，再根据该平台估计背景尺度。

### 6.1 安静平台

程序先按 2 分钟区间概括信号与局部极大值，再选择低信号、低局部峰活动的连续平台；如果找不到满足完整条件的连续平台，则回退到得分最低的一组时间区间。

设安静平台中的 scan 强度样本为 $X$，局部极大值高度样本为 $L$。主要背景统计量包括：

$$
Q_{0.90}(X),\quad Q_{0.99}(X),\quad Q_{0.75}(L)
$$

以及稳健波动：

$$
\sigma_{\mathrm{MAD}}
=1.4826\times
\operatorname{median}
\left|X-\operatorname{median}(X)\right|
$$

### 6.2 峰高和 prominence

primary marker 的基础峰高候选为：

$$
H_{\mathrm{body}}
=\max\left(
6Q_{0.90}(X),
4Q_{0.75}(L)
\right)
$$

如果正背景尾部估计：

$$
H_{\mathrm{tail}}
=Q_{0.99}(X)+3\sigma_{\mathrm{MAD}}
$$

是有限、为正、并且低于 $H_{\mathrm{body}}$，程序使用它作为较合理的背景尾部上限。峰的 prominence 门槛为：

$$
P
=\max\left(
0.8Q_{0.75}(L),
3\sigma_{\mathrm{MAD}}
\right)
$$

prominence 不是峰顶的绝对高度，而是峰顶相对两侧基线凸出多少。一个点即使很高，如果它只是高平台上的小波纹，也可能没有足够 prominence。

在极稀疏、高对比度而背景估计高于整条信号的特殊情况下，程序还有受限回退：以整条信号最大值的 10% 作为峰高尺度，并保留正的 prominence。这个回退只防止明显峰因稀疏背景估计失败而全部消失，不改变 marker 的质量窗口。

### 6.3 最终局部峰

最终事件峰必须同时满足：

- 是 marker trace 上的局部峰；
- 峰高至少为 $H$；
- prominence 至少为 $P$；
- 与另一个已选峰至少相隔约两个典型扫描间隔。

最后一条是检峰器的数值去重条件。对典型约 `0.103 s` 的扫描间隔，它约为 `0.206 s`，但实际值由文件自身的扫描时间估计。

这和后面用于人工审阅提示的 `0.60 s` **不是同一个参数**。

## 七、换一个 marker 时，程序究竟复用了什么

如果把 marker 从 `760.5851` 改成 $M'$，程序会：

1. 对每个 scan 改为读取 $M'\pm12$ ppm；
2. 重新生成 $x_s(M')$；
3. 在新 trace 上重新找安静平台；
4. 用新 trace 自己的背景分位数和 MAD 估计峰高与 prominence；
5. 用同一套局部峰规则生成新的自动事件；
6. 把 $M'$、参数、源文件指纹和检测代次写入新项目证据。

所以，用户担心的“是不是把 `760.5851` 的算法直接复用到别的 m/z”需要分两层回答：

### 7.1 从软件和数学上说：是

代码不会为另一个 m/z 自动切换成另一套专属峰形模型。它复用同一套：

- ±12 ppm 取窗；
- 每 scan 最大强度；
- 安静平台；
- 自适应峰高；
- 自适应 prominence；
- 约两个 scan 的最小峰距。

它不是把 `760.5851` 的**绝对强度阈值**硬套过去，因为阈值会根据新 trace 的背景重新估计；但它确实假设“新 marker 仍适合用同一种 trace 定义和峰形规则描述”。

### 7.2 从科学验证上说：不能因此视为可靠

另一个离子可能出现以下情况：

- 并非每个细胞事件都会产生该离子；
- 背景持续偏高，不再具有清楚的事件型尖峰；
- 峰更宽、更窄、拖尾更强或出现多峰结构；
- ±12 ppm 内存在其他离子，最大强度被干扰物占据；
- 不同时间段的质量误差或离子丰度结构不同；
- marker 与真正细胞事件的召回率或特异性不足。

自适应背景只能适应信号尺度，不能自动证明这些科学前提成立。

## 八、为什么 `760.5851` 是唯一常规推荐

当前证据等级如下：

| 设置         | 已有证据                                                       | 产品定位             |
| ------------ | -------------------------------------------------------------- | -------------------- |
| `760.5851` | 四个大型真实 MS 源回归；完整项目、检测、审阅、重开和导出链验证 | 默认值；唯一常规推荐 |
| 其他 m/z     | 参数校验、项目绑定和合成非默认值的精确取窗测试                 | 实验性               |

合成测试能证明：输入另一个 m/z 后，程序读取了正确的 ±12 ppm 窗口，没有偷偷继续读取 `760.5851`。

它不能证明：

- 新 marker 的事件召回率；
- 额外误检率；
- 与人工判断的一致性；
- 峰形和峰宽是否适合当前 detector；
- 生物学含义；
- 跨文件和跨批次稳定性。

因此，当前产品规则冻结为：

> 普通项目保留 `760.5851`。任何非默认 marker 都必须明确标为实验性，并新建独立项目；不得与默认项目混在一起解释，也不得宣传为已经验证的通用 marker 能力。

本文件暂不列举或推荐其他候选 marker。要把某个候选升级为常规选项，至少需要真实数据中的人工事件对照、召回与误检比较、峰形审查、跨文件复现和源文件只读回归。

## 九、固定 QC marker `782.5616` 是什么角色

无论 primary marker 是否修改，解析器都会另外提取固定的 `782.5616 ±12 ppm` QC trace。

它用于保存辅助质量证据，例如：

- QC marker 峰顶强度；
- QC marker 的实测 m/z 与 ppm 误差；
- primary/QC 的强度比。

但它不生成自动事件，也不会因为 primary/QC 比值不理想就直接删除事件。当前 detector 只对 primary marker trace 调峰；QC trace 是证据，不是第二个投票检测器。

## 十、`0.60 s` 相邻阈值与 marker 检峰的关系

`0.60 s` 不参与 m/z 取窗，也不决定 marker trace，更不参与最初的 `find_peaks` 调峰。它只在自动峰已经生成后，标记哪些事件需要更谨慎地人工审阅。

设自动事件按峰顶时间排序为：

$$
t_1^{(0)}<t_2^{(0)}<\cdots<t_N^{(0)}
$$

上标 $(0)$ 表示不可变的原始自动峰顶。对事件 $i$：

$$
d_{i,\mathrm{prev}}^{(0)}=t_i^{(0)}-t_{i-1}^{(0)}
$$

$$
d_{i,\mathrm{next}}^{(0)}=t_{i+1}^{(0)}-t_i^{(0)}
$$

缺少的一侧视为不存在。最近距离为有限两侧距离的最小值：

$$
d_i^{(0)}
=\min\left(
d_{i,\mathrm{prev}}^{(0)},
d_{i,\mathrm{next}}^{(0)}
\right)
$$

原始自动风险定义为：

$$
R_i^{(0)}
=\mathbf 1\left(d_i^{(0)}<0.60\ \mathrm{s}\right)
$$

注意是严格小于。恰好 `0.60 s` 不标记。

### 10.1 一个小例子

三个自动峰顶分别在：

```text
10.00 s    10.40 s               11.30 s
   A -------- B -------------------- C
       0.40 s          0.90 s
```

- A 的最近距离是 `0.40 s`，有风险；
- B 的最近距离是 `min(0.40, 0.90) = 0.40 s`，有风险；
- C 的最近距离是 `0.90 s`，无风险。

因此同一对近邻峰的两边通常都会被标记。这项提示不合并或删除 A、B，也不改变它们的事件身份。

### 10.2 为什么继续保留 `0.60 s`

`0.60 s` 来自冻结的 LMA Studio v0.4.4 event caller，是一条保守的人工复核线。它目前没有被 MS Event Studio 的独立人工真值集重新拟合成所谓“最优阈值”。

但它的作用不是决定事件存在与否，而是提醒批量操作不要自动越过潜在近邻，所以保留一个偏保守的默认值是合理的。当前决定是继续保留 `0.60 s`，不因界面观感随意调整。

## 十一、原始风险和实时风险为什么必须分开

### 11.1 当前已经实现的证据

项目创建时，软件按原始自动峰顶 $t_i^{(0)}$ 计算并永久保存 $R_i^{(0)}$。人工调整峰顶不会改写这项值。

这样做的意义是保留历史事实：

> 检测器最初给出这个事件时，它是否与另一个自动事件过近？

即使用户后来把峰顶移开，原始风险也不能被擦掉，否则审计会失去“自动结果当时是什么样”的证据。

### 11.2 当前已经实现的实时规则

软件会在当前 active events 的现时峰顶上另算一套实时风险。设当前峰顶为：

$$
t_1<t_2<\cdots<t_K
$$

按完全相同的最近邻逻辑定义：

$$
d_i^{(\mathrm{live})}
=\min\left(
t_i-t_{i-1},
t_{i+1}-t_i
\right)
$$

$$
R_i^{(\mathrm{live})}
=\mathbf 1\left(d_i^{(\mathrm{live})}<0.60\ \mathrm{s}\right)
$$

这项值会随着人工调峰、添加遗漏峰或其他当前事件变化而重算，但不会覆盖 $R_i^{(0)}$。

批量保留采用两者的逻辑或：

$$
R_i^{(\mathrm{skip})}
=R_i^{(0)}\lor R_i^{(\mathrm{live})}
$$

只要任意一项成立，批量保留就跳过该事件，留给人工判断。

### 11.3 为什么不能只留其中一项

只保留原始风险会漏掉人工编辑产生的新近邻：

```text
原始：A=10.00 s，B=10.80 s → 原始无风险
后来：B 调到 10.50 s          → 实时有风险
```

只保留实时风险又会擦掉原始自动结果的历史问题：

```text
原始：A=10.00 s，B=10.40 s → 原始有风险
后来：B 调到 11.00 s          → 实时无风险，但原始风险仍应保留
```

用逻辑或跳过最保守，也最符合批量操作的目的：宁可少自动保留几个事件，也不自动跨过任何一类近邻风险。

界面把“自动识别时”和“按当前峰顶”分开显示；人工补充事件没有自动识别时的位置，因此显示“不适用”。实时计算使用全部 active events，不受当前筛选、审阅状态或可见窗口限制。批量提交会在写事务中校验完整 active 事件修订集合，防止另一窗口恰好移动或添加近邻时仍沿用过期判断。审计记录使用的阈值、并集跳过数以及两类分项计数；两类分项可能指向同一个事件，因此不能相加当作总数。

## 十二、哪些参数不能混在一起理解

| 参数                      |          默认值 | 影响什么                                    | 不影响什么                   |
| ------------------------- | --------------: | ------------------------------------------- | ---------------------------- |
| primary marker m/z        |    `760.5851` | 每个 scan 从哪一个质量窗口提取主信号        | 不直接决定峰间时间距离       |
| marker tolerance          |        ±12 ppm | 哪些质心进入 marker 窗口                    | 用户当前不能修改             |
| detector minimum distance | 约 2 个扫描间隔 | `find_peaks` 不重复选择几乎同一个数值山顶 | 不是人工近邻风险线           |
| nearby-event threshold    |      `0.60 s` | 原始/实时风险提示和批量保留跳过             | 不调用、不合并、不删除自动峰 |
| QC marker                 |    `782.5616` | 辅助质量证据                                | 不生成事件                   |

最常见的误读是把 `0.60 s` 当作 detector 的最小峰距。如果真是这样，距离小于 `0.60 s` 的两个峰在检测阶段就不可能同时存在，也就没有必要再提示人工审阅。当前设计恰恰相反：检测器可以保留更近的候选，`0.60 s` 只负责把它们从批量自动保留中挡下来。

## 十三、普通用户应该怎么选

### 常规项目

- marker m/z 保持 `760.5851`；
- 相邻阈值保持 `0.60 s`；
- 不需要因为某个文件强度更高或更低而手动改 marker，峰高门槛会根据本文件背景自适应。

### 实验性 marker 研究

只有在有明确科学假设和验证方案时，才使用非默认 m/z：

1. 新建独立项目，不复用默认 marker 项目；
2. 明确标记为实验性；
3. 与人工事件判断或独立事件坐标比较；
4. 检查召回、额外检出、峰形、质量误差和跨文件稳定性；
5. 在证据完成前，不把它升级为常规推荐。

当前不讨论具体候选 marker，也不根据单个漂亮截图推荐新质量。

## 十四、已知限制和不作出的声明

1. `760.5851` 是经过当前真实数据回归的操作性 marker，不等于仅凭 m/z 完成化学鉴定。
2. ±12 ppm 是当前冻结容差，不是所有仪器、所有质量或所有采集模式的普适定理。
3. 每 scan 取最大强度能避免简单求和膨胀，但如果窗口内有强干扰物，仍可能选中干扰物。
4. 自适应背景能调整强度尺度，不能自动验证另一个 marker 的生物学召回率或特异性。
5. `0.60 s` 是保守审阅提示，不是由当前人工真值重新学习出的最优分类边界。
6. 原始自动风险必须不可变；实时风险是另一个派生视图，两者不能互相覆盖。
7. 当前实现会分别呈现原始风险和实时风险；不能把两者合并成一个来源不明的标记。

## 十六、冻结决定

截至 2026-08-20，产品决定为：

1. `760.5851` 保持默认，并作为唯一常规推荐的 primary marker；
2. 所有非默认 marker 明确标为实验性，不在本阶段讨论具体候选；
3. marker 容差固定为 ±12 ppm；
4. 相邻事件阈值保留 `0.60 s`；
5. 原始自动风险永久保留为不可变审计证据；
6. 另算基于当前峰顶的实时风险；
7. 批量保留时，只要原始风险或实时风险任意一个成立，就跳过该事件；
8. 两类风险在界面和审计中分开表达，分项计数允许重叠，总跳过数按并集去重。
